# UART0 / SmartDMA / RS485 长时间回显测试

先将当前工程重新编译、烧录；板上仍运行旧固件时不会出现 `U0EV`。UART0 保持原样按收到的长度原样回传，不解析或修改测试帧。UART1 只输出诊断，串口1回显任务在 `source/MCXA176_V6.3.c` 中已停用。两路均为 115200、8N1；PC 端 UART0 必须使用能自动控制收发方向的 RS485 适配器，UART1 使用 3.3 V TTL 串口适配器，两端共地。不要同时用别的串口助手占用这两个 COM 口。先暂时断开板端 A/B 进行一次短测试，确认 PC 适配器不会把自己发送的数据本地回显；否则上位机会把适配器的本地回显误判为板端正常回显。

安装 `pyserial` 后，在项目根目录运行（把 COM 号改为实际端口）：

```powershell
py -3 -m pip install pyserial
py -3 MCXA176_V6.3/tools/uart0_loopback_probe.py --port0 COM5 --port1 COM6
```

脚本默认每秒向 UART0 发送 16 字节、带序号/反码/CRC16 的变化测试帧；16 字节可完整放进下位机的 `U0EV HEX`，便于逐字节对照。读回字节与发出字节逐字节比较。持续运行直到按 Ctrl-C。`--duration 3600` 可运行一小时，`--output D:/uart0_probe_1` 可指定新的输出目录。目录内 `events.jsonl` 包含每次发送、UART0 原始接收片段、成功/超时/不匹配结果和 UART1 文本行；`uart1_raw.bin` 原样保存 UART1 字节，供检查上位机分包或乱码。出现异常后，保留整个目录，不只截取屏幕最后几行。

UART1 事件格式：`U0EV N... K... C接收帧数/发送请求数 B恢复次数 R接收状态 T发送状态 L长度 F错误标志 S串口状态 rem剩余字节 D方向 HEX前16字节`。`N` 连续递增；`K1` 是 RX 成帧，`K2` 是 TX 启动，`K3` 是接收错误，`K4` 是接收恢复，`K5` 是 UART 发送完成，`K6` 是回传 API 失败（此时 `F` 为返回状态码）。`D0` 为接收，`D1` 为发送。`U0SD` 的 `Q` 是事件队列丢弃数，必须保持 0；`FAIL` 是回传 API 失败次数。`U0DATA` 只是最近一帧快照，定位偶发错误时以 `U0EV` 为准。

分析顺序：

1. 找到 `events.jsonl` 中第一条 `result` 为 `timeout` 或 `mismatch` 的记录，复制该记录的 `seq`、`expected`、`got`。
2. 对照邻近的 `U0EV K1/K2` 的 `L` 和 `HEX`。若 `K1` 已错误或一包产生多个 `K1`，先查 A/B、电平、波特率、发送端字节间隔以及 IDLE 分帧；若 `K1` 正确而 `K2` 错误，查固件缓冲区；若二者正确而 PC 读回错误，查 UART0 TX、RS485 方向切换与总线。
3. 若相邻出现 `K3/K4`，记录 `F`、`S`、`rem` 和 `D`：可区分接收期间的帧/噪声错误与方向切换附近的错误。不要仅看 `U0SD E`，它是累计标志。

可选分帧压力测试：先完成默认连续发送测试，再单独运行 `--split-after 8 --split-gap-ms 2`。这会故意在第 8 字节后暂停 2 ms，超过当前 UART0 的 4 字符 IDLE 判帧间隔（115200 8N1 约 0.35 ms）。此模式用于验证“发送工具的字节间隔导致拆帧”假设，不代表正常回显必须通过该测试。

注意：脚本不能代替逻辑分析仪测量 UART0_TX、UART0_RX 和 RS485_EN 的真实边沿；如果 `K1/K2` 数据正确但 PC 读回仍错，下一步需同时抓这三路及 A/B 差分波形。
